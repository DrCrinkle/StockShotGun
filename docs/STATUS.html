Multi-broker reverse-split arbitrage tool, agentic-first. One MCP surface fans out across 13 brokerage integrations with per-leg-token-validated safety enforcement — plus, as of July 2026, automated reverse-split detection feeding the buy queue.

301 tests passing 38/53 ISCs 12 MCP tools 13 brokers ADR 0006 shipped Python 3.14, async-first

What it does

Submits the same order to many brokerage accounts simultaneously. Primary use case is reverse-split arbitrage — buy across N brokers before the split, wait, sweep to detect post-split share arrival per broker, propose sells when legs are ready. Candidates now arrive two ways: a human-pasted community recap, or (new) an automated scan of the Nasdaq splits calendar. Every order — buy and sell, from every surface (CLI, TUI, MCP) — goes through the same ExecutionEngine two-step propose/execute flow with per-leg confirmation tokens bound to a single-target intent hash. There is no single-call live order path. Code enforces safety; prompts do not.

Architecture

ADR 0006 (accepted 2026-07-02) promoted the old agent-only Router to ExecutionEngine — the one core every surface sits on top of. CLI, TUI, gated CLI, and MCP clients all call the exact same propose_order / execute_order, which runs through the enforcement gate and fans out over a BrokerPort to in-process or subprocess-isolated brokers. A new signals layer (Nasdaq splits calendar) feeds candidate tickers into the same buy queue the human recap parser already used.

Components

Enforcement core src/enforcement/

The gate. 10 modules. Every order path imports it; the build fails if anyone bypasses.

  • Per-leg single-use tokens bound to single-target intent hash
  • Per-order + per-day USD limits (env-configurable)
  • Corporate-action freeze list
  • Per-broker circuit breaker (3 errors → open)
  • Settled-cash + PDT pre-check
  • Tamper-evident hash-chained audit log
  • SQLite-backed proposal store with F2c per-leg schema

Per-broker MCPs src/agentic/brokers/

13 subpackages, one per broker. Each runs as python -m agentic.brokers.<name> — its own MCP server process.

  • Robinhood, Tradier, TastyTrade, Public, Firstrade
  • Fennel, Schwab, BBAE, DSPAC, SoFi
  • Webull, Wells Fargo, Chase
  • Each owns its credentials, rate limiter, circuit-breaker state
  • 4 tools per broker: place_at_broker, get_holdings_at_broker, list_accounts_at_broker, health_check

ExecutionEngine src/execution/engine.py ADR 0006

The core, promoted from the old agent-only Router (accepted 2026-07-02). Every surface below is a thin adapter over this one class.

  • propose_order, execute_order, place_order (one-shot)
  • validate_targets — pre-flight broker validation, moved off the old cli_bridge
  • get_rsa_trade, run_sweep, sell_arrived
  • scan_signals, dismiss_signal, promote_signal (new)
  • Imports only enforcement/ + brokers/ — never agentic/, layering-test-locked

Router MCP src/agentic/router/

The agent-facing FastMCP surface (ssg-router), now a pure transport wrapper around ExecutionEngine — 12 tools total.

  • list_brokers — health + flags across all 13
  • get_holdings — fan-out holdings query (sanitized)
  • propose_order, execute_order, place_order
  • get_rsa_trade, run_sweep, sell_arrived, recap_ingest
  • scan_signals, dismiss_signal, promote_signal — new, Nasdaq calendar signals

Signals src/signals/ new

Automated reverse-split detection, shipped 2026-07-02. Deterministic — no LLM involved in what the data is, only in whether to play it.

  • signals/nasdaq.py — Nasdaq splits-calendar fetch + parse
  • calendar_signals table in AutomationRecapStore — idempotent upsert, never resurrects terminal states
  • Worthwhile signals promote into the existing buy_signals queue — a second source next to chat recaps, not a parallel pipeline
  • CLI: signals scan / signals list
  • NULL effective date = immediately due; promote refuses past-dated signals

CLI + TUI, all on the engine

main.py + tui/app.py now call ExecutionEngine.propose_order / execute_order directly. cli_bridge.py is deleted — grep -rn cli_bridge src tests returns zero.

  • All sites on one path: buy/sell, batch, automate, TUI submit, TUI retry
  • Real per-account fan-out for every caller (was one synthetic "primary" leg pre-ADR-0006)
  • --dry-run is now a full-pipeline rehearsal — limits/freeze/reconciliation/token-minting all run, nothing is placed
  • render_execution_result / aggregate_execution_results (cli/common.py) replace the old hand-rolled reshape

Status feed src/cli/status.py new

Read-only aggregate JSON snapshot for the PAI Pulse dashboard to poll — shipped 2026-07-02 as the repo-side half of the agent-operated RSA engine spec.

  • python3 main.py status (via the global --output json flag)
  • Open trades + positions by sweep status
  • Signal-queue counts: calendar_signals, buy_signals, pending_sell_triggers
  • Staged-proposal detail, execution history, per-play P&L: not yet in the snapshot

Telemetry src/execution/telemetry.py

Structured logging wraps every engine + broker method. Audit-log is separate (and tamper-evident); telemetry is for ops.

  • Daily-rotated JSONL at logs/mcp-YYYY-MM-DD.jsonl
  • Token prefixes only (8 chars + ellipsis)
  • Credential-shaped keys dropped before write
  • Explicit dry_run field — no arg-parsing needed

The two-step gate

  $ python -m agentic.cli propose buy 10 TSLA --brokers Fennel,Tradier \
      --price 5.0 --live
  {
    "proposal_id": "2834cc72…",
    "estimated_usd": 100.0,
    "leg_count": 2,
    "valid_until_ts": 1779906615.7,
    "skipped_brokers": []
  }

  $ python -m agentic.cli execute 2834cc72… --live
  {
    "success_count": 2,
    "failure_count": 0,
    "results": [
      {"broker": "Fennel",  "ok": true, "idempotency_key": "45bd…"},
      {"broker": "Tradier", "ok": true, "idempotency_key": "8a1c…"}
    ]
  }

Live order placement requires both steps with explicit --live. The agent never sees a single-call live order primitive — place_order with dry_run=False and no proposal_id is rejected at the router (ISC-18). Per-leg tokens are single-use and bound to a SHA-256 hash of the normalized intent — a tampered or replayed token gets intent_mismatch at the broker boundary.

The mission statement

Code enforces safety; prompts do not. The agent decides which RSA opportunity to enter, when to sweep, when a leg is ready to sell — and now, which calendar signal is worth playing. The code decides dollar limits, intent-hash binding, single-use tokens, the freeze list, circuit breakers, audit-log integrity, and which actions require explicit principal confirmation. The ExecutionEngine is the core every surface — human CLI, TUI, or agent — sits on top of as a thin adapter: one fan-out path across 13 brokers, not thirteen separate implementations of the same safety rules.
