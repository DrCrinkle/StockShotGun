StockShotGun

Multi-broker reverse-split arbitrage tool, agentic-first. One MCP surface fans out across 13 brokerage integrations with per-leg-token-validated safety enforcement.

135 tests passing 38/53 ISCs 8 MCP tools 13 brokers Python 3.14, async-first

What it does

Submits the same order to many brokerage accounts simultaneously. Primary use case is reverse-split arbitrage — buy across N brokers before the split, wait, sweep to detect post-split share arrival per broker, propose sells when legs are ready. Every order — buy and sell, gated CLI and legacy CLI — goes through a two-step propose/execute flow with per-leg confirmation tokens bound to a single-target intent hash. There is no single-call live order path. Code enforces safety; prompts do not.

Architecture

Three layers. The enforcement core is the gate. Per-broker MCPs are the isolation boundary. The router is the agent's surface. CLI, TUI, gated CLI, and MCP clients all route through the same gate.

Components

Enforcement core src/enforcement/

The gate. 10 modules. Every order path imports it; the build fails if anyone bypasses.

  • Per-leg single-use tokens bound to single-target intent hash
  • Per-order + per-day USD limits (env-configurable)
  • Corporate-action freeze list
  • Per-broker circuit breaker (3 errors → open)
  • Settled-cash + PDT pre-check
  • Tamper-evident hash-chained audit log
  • SQLite-backed proposal store with F2c per-leg schema

Per-broker MCPs src/agentic/brokers/

13 subpackages, one per broker. Each runs as python -m agentic.brokers.<name> — its own MCP server process.

  • Robinhood, Tradier, TastyTrade, Public, Firstrade
  • Fennel, Schwab, BBAE, DSPAC, SoFi
  • Webull, Wells Fargo, Chase
  • Each owns its credentials, rate limiter, circuit-breaker state
  • 4 tools per broker: place_at_broker, get_holdings_at_broker, list_accounts_at_broker, health_check

Router MCP src/agentic/router/

The agent-facing fan-out surface. python -m agentic.router starts the stdio MCP server.

  • list_brokers — health + flags across all 13
  • get_holdings — fan-out holdings query (sanitized)
  • propose_order, execute_order, place_order
  • get_rsa_trade, run_sweep — RSA persistence + classification
  • sell_arrived — one-shot propose-sells for ARRIVED legs

Gated CLI src/agentic/cli.py

Operator surface that routes every order through the gate. Parallel to legacy main.py, becomes the documented default for new tooling.

  • list-brokers, holdings, dry-run
  • propose, execute (two-step required for live)
  • audit-verify — walks the audit hash chain
  • Static check fails the build on direct broker SDK calls

Legacy CLI + TUI

main.py + tui/app.py rewired to route every execution through the Router via execute_via_router.

  • All 5 sites gated: buy/sell, batch from-file, automate, TUI submit, TUI retry
  • Per-leg-token validation now active on the legacy path
  • Existing --dry-run, --mock-brokers, broker selection preserved
  • Backwards-compatible results shape for compute_trade_exit_code

Telemetry src/agentic/_telemetry.py

Structured logging wraps every router + broker MCP method. Audit-log is separate (and tamper-evident); telemetry is for ops.

  • Daily-rotated JSONL at logs/mcp-YYYY-MM-DD.jsonl
  • Token prefixes only (8 chars + ellipsis)
  • Credential-shaped keys dropped before write
  • Explicit dry_run field — no arg-parsing needed

The two-step gate

  $ python -m agentic.cli propose buy 10 TSLA --brokers Fennel,Tradier \
      --price 5.0 --live
  {
    "proposal_id": "2834cc72…",
    "estimated_usd": 100.0,
    "leg_count": 2,
    "valid_until_ts": 1779906615.7,
    "skipped_brokers": []
  }

  $ python -m agentic.cli execute 2834cc72… --live
  {
    "success_count": 2,
    "failure_count": 0,
    "results": [
      {"broker": "Fennel",  "ok": true, "idempotency_key": "45bd…"},
      {"broker": "Tradier", "ok": true, "idempotency_key": "8a1c…"}
    ]
  }

Live order placement requires both steps with explicit --live. The agent never sees a single-call live order primitive — place_order with dry_run=False and no proposal_id is rejected at the router (ISC-18). Per-leg tokens are single-use and bound to a SHA-256 hash of the normalized intent — a tampered or replayed token gets intent_mismatch at the broker boundary.

The mission statement

Code enforces safety; prompts do not. The agent decides which RSA opportunity to enter, when to sweep, when a leg is ready to sell. The code decides dollar limits, intent-hash binding, single-use tokens, the freeze list, circuit breakers, audit-log integrity, and which actions require explicit principal confirmation. The router is the agent's surface — one fan-out tool across 13 brokers is strictly more useful than 13 separate broker MCPs.
